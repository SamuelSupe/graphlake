| Oracle 未约束 NUMBER、FLOAT | **复审修复。** 恢复未定精度数值的精确文本映射，保留已声明类型的整数与 Decimal128。需要数值计算的源列可在视图中声明 `NUMBER(p,s)`。 |

| Worker 使用 Coordinator 的墙上时钟 | **修复。** 接单、算子分区及 CSR 分区都传剩余毫秒，接收时换成本机单调时钟；混合旧版本走兼容分支。 |

| 分布式 collect 溢写句柄 | **加固。** 溢写令牌仅在注册它的进程内有效；相关聚合保留在查询所在 Worker，同一查询的其他可分布阶段仍可下发。 |

## 图查询与源读取

| 条目 | 核对结论与处理 |
| --- | --- |
| 变长路径扩展过宽 | **部分优化。** 同一 MATCH 或紧接在单节点 MATCH 后的列表条件可缩小起点，也覆盖绑定后变为字面量的参数；经复杂中间阶段或 UNWIND 的动态键仍可能扫描全图。 |
| 相关 CALL 遇到 LIMIT 逐键规划 | **优化。** 较大外层页可批量求值不同导入键，按键截取前缀并保留外层顺序。小页优先单键短路，连续空批次后可扩大批量。无法批量改写且无动态子表的查询复用物理计划，仍按键执行。查询准备在需要时使用备用栈，覆盖 Linux 夹具复现的嵌套 CALL 栈溢出。 |
| 本地 CSR 只能留 8 MiB 一份 | **优化。** 改为总计 64 MiB 的有界缓存，最多四项，使用文件标识检查替换。 |
| Auto 继续读旧 CSR | **修复。** 只自动使用能重新核对且未改变的来源版本；显式 Cached 仍支持历史快照及离线读取。 |
| Gremlin 多标签分支展开、未做 CSR 和 bulking | **优化。** 多标签遍历、隐式多边类型跳转和多实体属性排序共享可溢写的上游输入。Gremlin CSR 和遍历器 bulking 仍是独立的审查项。 |
| 无定点 allShortestPaths 重复初始化全图数组 | **优化。** 同一次遍历复用 BFS 工作区，只重置上一轮实际访问的点；稠密图本身仍可能有平方级访问和更多输出路径。 |
| Gremlin where/project/select 全局排序及重复上游 | **成立，保留。** 当前用顺序或行身份表达遍历器作用域；未移除这些语义屏障。 |
| 远程 Parquet 串行范围读取 | **优化。** 对近邻范围合并，有限并发，保留解码顺序并校验固定版本；同一次查询重用已读取的文件尾部。范围回归的 4 个切片从 4 次 GET 降为 2 次。 |
| PostgreSQL 文本和 UUID 索引 | **部分优化。** 文本等值增加原生索引候选条件，并保留精确的 C 排序规则复核；规范 UUID 等值使用原类型比较。非规范文本及其他比较保留原语义，实际计划受索引和统计影响。 |
| MySQL 文本等值索引 | **优化。** 已支持的 UTF8MB4 列加原生等值条件，保留二进制复核，避免改变大小写和尾空格语义。 |
| Snowflake／Oracle 整数全映射成 Decimal128 | **不成立。** 基线已按声明精度映射能安全容纳的整数，较宽值不能无损转成 Int64。是否传回整表还取决于条件类型和查询形状。 |
| MongoDB 忽略过滤 | **部分优化。** 给顶层整数比较和布尔等值生成服务端条件；采样和本地复核保留。字符串表示合并了 BSON String、ObjectId、Decimal128 和数组，不能统一按文本下推。 |
| Iceberg 不接受执行计划过滤、逐批桥接 | **部分优化。** 除模型过滤外，接收 DataFusion 的安全整数条件推给 Iceberg 并保留本地复核。IPC 桥接保留 Arrow 58／59 依赖边界。 |
| 每次重新读取湖仓元数据 | **部分优化。** Parquet 并行读取远端文件尾部，并在查询内复用。Delta 当前快照仍按查询解析；跨查询固定版本元数据缓存没有改动。 |
| SQLite 逐单元分配及 SQL Server 全部文本转换 | **部分优化。** SQLite 基线对整数等使用借用读取和内联标量，文本或 Blob 仍拷贝。SQL Server 的布尔和整数列改用原生 TDS 返回。 |

## 服务容量、其余语义及稳定性

| 条目 | 核对结论与处理 |
| --- | --- |
| 多输入、SCD2、无键边全量物化 | **有限成立，保留。** 现有候选键可以限制部分来源读；验证同键冲突、生成无键边身份的范围不能直接用任意属性或 LIMIT 截断。 |
| 配置的对象存储 Parquet 不命中业务键证明 | **修复。** 与本地文件共用完整扫描证明机制，对象替换后失效。 |
| 准入独立且图属性补齐前释放预留 | **部分修复。** Stage 共用准入额度；图结果补取属性时继续保留来源内存和查询租约。HTTP 校验、探索和加载仍有各自队列，不能把 `--query-slots` 当成进程 RSS 上限。 |
| 每次重读／重哈希归档模型 | **部分优化。** Worker 按不可变模型版本缓存验过的引擎。Coordinator 的本地归档验证及模型列表读取保留，以便发现损坏或外部文件编辑。 |
| etcd 高频轮询、每查询单独申请租约 | **部分优化。** 同一 Coordinator 五秒内复用查询元数据租约。租约原本也有 TTL；快速结果轮询和心跳仍采用现有方式。 |
| Worker 只运行一个远端 stage | **优化。** 根据接单后剩余内存预留一至四个远端槽；没有额外可用预算时仍为一个。 |
| CSR 旧代次及 Catalog manifest 未自动清理 | **修复。** 当前 CSR 指针、执行中的任务、生效目录和未过期回执为回收保护根。已写入至少 24 小时的无引用对象先标记，24 小时后复查才删除。图探索可以读取仍在保留期的历史 CSR，便携备份包含自身目录内容。 |
| 审计同步、单机日志文件无上限 | **部分修复。** 文件按约 32 MiB 轮转并保留上一个文件；保留同步追加的可见性，HA 继续由服务日志承担留存。 |
| Databricks 和 SQL Server 无查询超时 | **不完全成立。** 引擎用查询总截止时间；Databricks 分页任务销毁时发取消，协议夹具已通过。SQL Server 的锁等待也受限，未新增服务端语句限时配置。 |
| PostgreSQL、MySQL、SQL Server 无连接超时 | **修复。** 在连接和握手边界应用查询预算。 |
| ClickHouse 只读账号不能下发 max_execution_time | **成立，保留兼容行为。** 只读配置拒绝更改时改由服务端 profile 设置，GraphLake 客户端仍有截止时间。 |
| SQLite 忙等待最多 100 ms | **修复。** 在请求预算内等待锁，取消后在下一次锁重试时退出。 |
| Trino 在夏令时回拨报错 | **修复。** 在 Trino 端转换为 UTC 后再序列化，保留两个不同时刻及小数精度。 |
| ClickHouse DateTime 可变成 UInt32 | **修复。** 对声明为 DateTime 的字段投影到 DateTime64，以保留 Arrow 时间戳类型。见 [ClickHouse 的 Arrow 类型行为](https://clickhouse.com/resources/engineering/convert-arrow-to-parquet)。 |
| etcd 210 ms 失败，单次 statvfs 让 Leader 下线 | **部分修复。** 基线已在多个 etcd 节点间重试只读操作，210 ms 是多端点的单次预算；单机和写入规则不同。目录探测改为连续两次失败才下线。 |
| 失去主权返回重复请求 ID | **修复。** 查询登记 CAS 失败后先确认主权，再区分可重试状态与真正重复 ID。 |
| 宽行固定 128 行使 CSR 构建失败 | **修复常见情形。** 探测压缩块大小并缩小批次；单行超过块上限仍明确失败。 |
| Cypher 内联属性、size(string)、关系唯一性 | **部分修复。** 显式定长模式支持作用域内表达式；字符串 size 按 Unicode 字符计算，并保留数组和 NULL。变长关系的动态过滤、通配模式及大量关系产生的成对唯一性约束仍有限制。 |
| Gremlin otherV 文本比较、未知 hasLabel、负权无向边 | **部分修复。** 未映射的 hasLabel 返回空。节点键和对应边端点的类型原本就必须相同，未证明文本编码在当前契约下造成错配。无向负权边形成可往返的负环，拒绝是正确的。 |
| 缓存和在线读取时邻居顺序 | **不保证顺序。** 未指定排序的结果可能不同，等长路径任取其一；本次没有增加隐含排序和结果承诺。 |
| 并发 /readyz 的第二个探针立即 503 | **修复快速重叠。** 在有限窗口内等待探针槽，仍可对超载或后端故障返回 503。 |
| 本地表更新配置推迟对账／调度错误静默 | **修复。** 不相关的配置编辑保留对账时点，记录单机调度非预期服务错误；托管调度仍使用各自结果确认流程。 |
| 导出挤掉他人下载票 | **修复单机。** 淘汰只适用于当前身份；其他票据占满配额时返回忙。 |
| 未认证请求通过 traceparent 强采样 | **修复。** 公共入口按本地采样，Worker 只从已认证的集群请求继承上游 trace。 |
| CSV 空字符串与 NULL | **修复文件表示。** 分别写带引号空字符串和无引号空字段；会主动合并两种 CSV 表示的客户端应使用 Parquet。 |
| DataFusion poll 持 std Mutex | **修复。** 在锁外 poll，超时任务可记录取消并唤醒消费者。 |

## 回归与测量

- 指定 Linux 主机在 SSH 握手阶段超时。将同一工作树同步到隔离的 Ubuntu 24.04 ARM64 虚拟机并校验源码哈希，使用 Rust 1.97.1 跑完常规回归，库 22 项、管理服务 18 项、查询引擎 71 项通过。Gremlin 用例覆盖四标签九跳以及等价的 `repeat()` 写法。
- Linux 另有 14 项 PostgreSQL、S3 和数仓协议夹具通过。默认线程栈下验证了嵌套 CALL。128 个不同命中键的查询发出 29 次 PostgreSQL 请求，经过 128 个空键再命中的 `LIMIT 1` 查询发出 41 次请求。
- 同一 Linux 虚拟机启动三个 etcd 3.6.5 成员及 RustFS 1.0.5，验证旧 Coordinator 写入隔离、Coordinator 重启与 Worker 丢失后的查询恢复、CSR 刷新失败行为，以及对象回收对当前指针、在途任务和未过期回执的保护。停止 etcd 主成员并重新选主后，回收用例再次通过。
- PostgreSQL 索引审查在指定主机的隔离实例上使用同一张 50,000 行表执行 `EXPLAIN ANALYZE`。文本与 UUID 谓词均从顺序扫描切换为各自的索引扫描，四个计划都读出同一条匹配记录。
- 以 `cargo test --locked --features admin --lib --bins --test engine --test admin` 运行常规组。当前改动涉及的 SQL Server、Oracle、MySQL、ClickHouse、MongoDB 和 Iceberg 生产实例仍需按实际部署配置验收。

- Ubuntu 24.04 ARM64 使用 Rust 1.97.1 通过 116 项常规 Rust 测试和 14 项 PostgreSQL、S3、数仓协议夹具。新增用例覆盖连续键的相关 CALL、聚合表达式排序、SQL Server 哨兵日期、Oracle 高精度业务键，以及 SCD2 新探索和旧游标跨有效期边界。

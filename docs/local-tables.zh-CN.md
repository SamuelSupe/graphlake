# 本地表与数据同步

本地表把外部源表的选定字段加载为 GraphLake 管理的 Parquet 副本。节点和边通过现有 Parquet 数据源读取副本，查询时不再连接外部源。管理流程参考 [PuppyGraph 的本地表](https://docs.puppygraph.com/modeling/data-sources/)与[加载、定时刷新管理](https://docs.puppygraph.com/modeling/managing-the-graph/)；接口和存储格式使用 GraphLake 自身约定。

## 使用流程

1. 配置外部数据源并保存模型草稿。在「图模型 → 本地表」或「数据源 → 本地表与同步」打开管理页。
2. 创建本地表，使用已有的源表浏览器选择表及字段。主键可由多个字段组成。需要增量更新时，同时设置主键与增量字段。
3. 选择创建后立即加载，或稍后执行「加载副本」或「更多操作 → 从源表全量加载」。任务在后台运行，页面可以关闭。历史保留最近 20 次任务，显示手动/定时、加载方式、读取行数、提交后的总行数和结果。
4. 加载成功后选择「更多操作 → 加入模型数据源」，再在节点或边的来源选择器中选择 `local_<表名>.data`；也可点击「更多操作 → 切换映射到本地」，将当前草稿里直接使用该外部表的节点、边及多表输入切换到副本。
5. 检查映射、保存草稿并发布。添加副本不会自动发布模型。若加载字段不足以覆盖已有映射，结构/数据校验会阻止发布；先补齐字段的新表，再切换。

列表顶部展示本地表数、已就绪副本、运行中任务与定时刷新概况，可按表名或来源搜索、按状态筛选。每张表展示刷新策略、最近成功行数和下次运行时间；「立即同步」使用该表配置的更新方式，执行时间线保留任务结果与行数。

源表、连接配置、选定字段、主键、增量字段在创建时固定，独立于后续模型草稿修改。连接凭据继续从原环境变量读取；修改变量后需按现有部署方式重启。若需要更换来源或字段，创建另一张本地表。刷新方式、间隔和超时可随时修改，并有版本冲突检查。

## 更新语义

| 方式 | 行为 |
| --- | --- |
| 全量加载 | 读取所选源表字段，完整写入新副本后原子替换，包含源表当前的插入、更新和删除。未指定主键时保留重复行。 |
| 增量更新 | 首次没有副本时执行全量读取；之后从已提交副本计算最大增量值，读取大于或等于此水位的行，按完整主键覆盖，保留其他旧行。 |
| 定时刷新 | 使用配置的全量或增量方式，每次任务结束后等待指定间隔，再提交下一次任务。失败也按相同间隔重试。 |

增量字段支持整数、日期和时间戳，必须非空。主键必须稳定、非空，在每批来源数据中唯一。每次插入或更新都必须推进该行的增量值。同步重读水位边界并按主键覆盖，使重试及同一水位的行保持幂等。MySQL、MariaDB 的 InnoDB 来源和 PostgreSQL 可下推受支持的日期与微秒时间戳水位，并在 GraphLake 复核候选行。MySQL 用 UTC 会话读取 TIMESTAMP，DATETIME 保留无时区时间。整数仍走各连接器已有的谓词路径。水位列上的索引可以减少数据库内部扫描，实际读取量取决于源端执行计划。

增量同步默认包含水位边界。创建本地表时可以指定 `lookback`，以 `>= 已提交水位 - lookback` 重读窗口内的数据。窗口单位使用 Arrow 增量字段的原始单位，例如整数字段的计数单位、Date32 的天或微秒时间戳的微秒。增量提交的水位保持单调，完整对账可在新快照中重建水位。字符串、整数和二进制主键及其复合键支持该选项。

`deleted_column` 指定已选字段中的非空布尔或整数标记，`true` 或非零表示删除完整主键。标记和水位随同一批输入处理，最高水位即使来自删除记录也会持久化。配置该字段需要支持键索引的主键格式。含实际删除的批次使用完整合并。没有可见变动且水位相同的重放保留代次。

物理删除、主键变化和窗口外迟到由全量对账捕获。`reconcile_interval_seconds` 可单独启用全量对账，默认关闭，最小 30 秒。增量和对账共享单表写锁，对账到期后优先于同表增量。失败保留旧副本、最近成功对账时间和已到期的对账计划。调度器退避后重试。单机副本在下次加载前清理可回收的旧分区。若查询仍固定旧代次，且旧分区超过引擎溢写预算，加载会等待后续重试。轮询间隔、加载耗时和 CSR 刷新共同决定可见延迟。

托管调度器每秒获取上次 etcd 修订之后有变动的表记录，每 60 秒刷新一次完整记录以处理删除。任务启动和恢复仍按 etcd 中的当前状态确认。

启用主键时，发现重复或空主键会使任务失败。增量字段类型不支持、字段丢失、字段类型变化也不会发布新副本。字段新增只有新建表并选择后才加载。任务失败或取消发生在提交前时，保留旧副本。提交点之后到达的取消不会撤销已提交的数据。

数据和水位来自同一个已提交快照。进程异常退出后，已提交副本仍可读取。未完成的任务在下次启动时记为「已中断」，可手动重试，已启用的定时任务也会恢复。对于带键索引的副本，如果退出发生在清单发布之后、历史写入之前，重启会从清单恢复该任务的 `committed_generation`。重试使用已提交水位。

若多文件快照的清单带有表结构，缺失旧数据文件时可以从源表全量重建。增量更新需要原快照完整。

当增量没有新行，或确认本次重读的小批边界记录所有字段值均相同时，服务记录任务结果并保留原副本。单列有符号整数主键的小批增量会利用行组统计定位旧记录。集中变更复用未改动的行组，在支持 reflink 的 Linux 文件系统上可共享磁盘块。分散变更只写入新增或替换的记录，通过清单记录各文件中被覆盖的位置。数据文件刷盘后，服务原子替换清单。查询使用同一份清单过滤旧行并读取新增记录，水位取本次提交中携带最新变更的文件的最大值。

字符串 UUID、16 字节 UUID、整数、变长二进制键及由这些类型组成的复合键，可使用写者本机的 SQLite 键位置索引。单列有符号整数继续使用行组路径。候选批次在加载批大小以内且暂存 Parquet 不超过 16 MiB 时，索引用完整类型化键定位旧行。确认水位边界的旧值时，读取对应的 Parquet 行组。GLPQ2 清单将数据、水位、类型、主键和任务 ID 一次发布。索引缺失、格式或代次不匹配时，会从已提交数据读取键列重建。第一次索引建立及索引重建的成本随副本规模增加。

清单最多引用 16 个基础分区和 15 个增量文件。新增批次将超出增量文件数或覆盖位置预算时，服务先把仍有效的增量行和本次变更写成一个文件。若合并后的增量超过 64 MiB，服务把该文件封存为基础分区。若基础文件被覆盖的位置超过 65,536 个，服务优先重写每字节能回收最多覆盖位置的基础分区，将基础表的覆盖位置降到上限的一半以内。已有的大型单文件会在首次整理时按行组切分。支持 reflink 的系统可以共享未改动的磁盘块，其他系统会复制切分时的已编码字节。

新文件刷盘后由一份清单原子发布。基础分区数量或封存大小达到上限时，服务可完整合并。全量刷新或较大批次可以生成一个基础 Parquet 文件。支持键索引的配置仍使用 GLPQ2 清单发布该文件。其他主键类型沿用原有路径。

读取多文件快照时，GraphLake 有界并发读取各文件的 Parquet footer，并在同一次查询中复用它们来裁剪行组。列与常量的等值过滤可在 Parquet 读取器中先求值，再读取命中行所需的宽列数据页。读取数据页和页索引时仍校验已固定的文件版本。

新的多文件快照清单同时记录表结构及各文件的有符号整数主键范围。主键等值查询可以在读取 footer 之前跳过范围不匹配的文件。范围涵盖物理行，重叠范围中的文件仍参与查询，覆盖掩码继续决定哪些行可见。旧清单及缺少精确范围的文件沿用原有读取方式。同步生成新清单时会从已有文件的精确行组统计补齐范围。

清单将足够密集的连续覆盖位置存为左闭右开的区间。分散的覆盖位置使用逐行位置列表。两种形式按实际覆盖行数计入同一预算，读取旧清单时也支持逐行位置列表。

GraphLake 的模型映射仍使用现有路径。处于清单模式时，可将完整查询结果导出为单份 Parquet 供外部工具读取。升级版本可读取原始单文件和 GLPQ1 清单。使用集群时，先升级所有读取 Worker，再写入 GLPQ2。需要回退到只支持 GLPQ1 的版本时，停同步并恢复升级前备份，或提前通过 GraphLake 导出副本并在旧版重新映射。

同一张表只运行一个任务，全服务最多同时运行两个加载任务；手动提交在繁忙时返回冲突或 `429`。定时任务在执行槽空闲后尝试，无积压队列，不补跑停机期间每个错过的时间点。间隔为 30–2592000 秒，单次超时为 1–43200 秒。关闭定时刷新不会取消已开始的任务，可单独点击「取消加载」。

本地副本延续现有 Parquet 来源版本检查。读取托管清单时，查询在选择清单前取得共享读锁，并持有到结果流释放，期间服务推迟回收旧文件。直接读取旧式单文件时，若刷新使已固定的文件版本变化，查询可能返回来源变化错误，可重新查询。模型 YAML 版本不固定本地数据版本，回退模型不会回退表中数据。集群模型可启用 `freshness.auto_refresh_csr`，使 CSR 跟进其依赖的本地代次。

## 管理 API

以下路径以 `/api/v1` 为前缀，仅管理员可操作，沿用会话认证和同源 `Origin` 校验。普通建模、发布、查询角色和服务账号不能管理同步任务。配置记录和 API 响应不包含环境变量中的凭据值。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /models/{id}/local-tables` | 列出定义、是否已有副本、刷新配置、下次运行时间和最近历史。 |
| `POST /models/{id}/local-tables` | 创建定义，返回 `201`；本身不触发加载。 |
| `PUT /models/{id}/local-tables/{name}` | 更新刷新方式、间隔和超时，提交当前配置 `revision`。 |
| `POST /models/{id}/local-tables/{name}/load` | 提交后台任务，返回 `202` 和任务 UUID；通过列表的 `history` 跟踪。 |
| `POST /models/{id}/local-tables/{name}/cancel` | 请求取消运行中的任务，返回 `202`。 |

创建请求示例（模型中已有 `ledger` 数据源）：

```json
{
  "model_revision": "模型当前草稿 revision",
  "name": "accounts",
  "source_table": "ledger.public.accounts",
  "columns": ["id", "name", "updated_at"],
  "key_columns": ["id"],
  "watermark_column": "updated_at",
  "mode": "incremental",
  "interval_seconds": 3600,
  "timeout_seconds": 3600
}
```

`model_revision` 不匹配返回 `409`。名称为 1–48 位字母、数字、下划线或连字符，首字符必须是字母或数字。字段最多 512 个，本服务最多 256 张本地表。新表读取已保存草稿中的连接信息，无需模型已发布。禁止以本服务管理的本地副本作为另一个同步任务的来源。

手动加载正文为 `{"mode":"full"}` 或 `{"mode":"incremental"}`。配置更新示例：

```json
{
  "revision": "本地表当前配置 UUID",
  "mode": "incremental",
  "interval_seconds": null,
  "timeout_seconds": 3600
}
```

`interval_seconds: null` 关闭定时刷新，`reconcile_interval_seconds: null` 关闭定时对账。状态为 `running`、`succeeded`、`failed`、`cancelled` 或 `interrupted`。`loaded_rows` 是本次写入暂存副本的行数，包含重读水位边界。`total_rows` 是合并后总行数。带键索引且实际发布新代的任务提供 `committed_generation`。成功任务包含可选的 `source_reads`，其中 `mysql_rows`、`postgres_rows` 等统计接收并解码的行数。`local_parquet_write_bytes` 统计来源暂存与完整合并生成的 Parquet 字节，带键索引的写入路径同时计入整理生成的 Parquet。数据库内部扫描量由数据库执行计划或指标提供。

本地表返回最近成功观察开始时间 `observed_at_ms`、任务完成边界 `observation_finished_at_ms`、最近成功全量对账的观察时间 `reconciled_at_ms` 和下次对账 `next_reconcile_at_ms`。新格式同时返回当前 `generation` 和类型化 `watermark`。时间使用 UTC Unix 毫秒，界面按浏览器时区显示。水位属于业务数据的时间轴。新鲜度查询按观察时间和对账时间计算。

## 存储与部署

普通表的副本、增量文件、定义和历史位于 `catalog/.graphlake-local/`。按部署手册停机备份整个 catalog，同时备份外部凭据配置。为旧副本、新副本、来源暂存和查询 spill 预留空间。服务启动时取得此目录的独占文件锁，同一目录只能由一个活动服务写入。启动恢复会清理中断的暂存文件，并在无活跃读者时回收未引用的增量文件。派生键索引位于写者本机的系统临时目录，恢复或切换写者后可重建。S3 托管表的同步工作区也在本机临时目录。托管表的派生 SQLite 索引位于该工作区，随工作区清理。`TMPDIR` 可为工作区和键索引指定本机磁盘。集群共享目录需要在各进程之间支持文件锁及原子替换。

文件模式下，读取 Worker 通过相同绝对路径访问该目录。启用 [S3 托管本地表](../deploy/cluster.md#s3-托管本地表) 后，新建副本以稳定表 ID 引用，Worker 只需访问 S3 和 etcd。HA Coordinator 在持有领导权且恢复验收通过后启动定时任务。托管表在数据加载结束时归还加载槽，尚未确认的发布结果最多重试 30 秒。结果仍未确认且任务已退出时，Coordinator 将该任务记为「已中断」。下一次同步从当前已提交清单和水位继续。现有 HA 手动、定时和 CLI 备份同时导出表定义、刷新策略、同步历史、已提交清单和它引用的文件。保留控制 JSON 与同级 `local-<id>`，详见[跨站恢复](../deploy/cluster.md#绑定恢复点并开放入口)。恢复验收期间业务入口和自动刷新关闭。验收后仍保留原同步周期，并暂停本地表定时任务，直至管理员重新保存刷新配置。手动增量同步可以先验证来源及原水位，首次使用键索引会重建位置缓存。

编辑器新增的本地表来源在文件模式下使用相对路径 `.graphlake-local/<id>.parquet`，S3 托管模式使用 `local-table://<id>`。异地可换 catalog 根目录，模型修订摘要保持一致。已有绝对路径的生效模型须恢复到相同路径，或先发布使用相对路径的新修订再备份。同步来源仍使用原配置及凭据环境变量。在原 catalog 根下的本地来源路径随目标根重新定位，目录外的来源仍需按目标站配置。

本地表和配置不随模型下线删除，运行中的同步也不受模型发布状态影响。停用时先关闭定时刷新，保留副本可继续支持历史模型。当前页面不提供删除副本、独立手工插入行、分区保留或 PuppyGraph 的分布/副本数等物理布局设置。

单机本地表任务的数据提交后，如果状态文件暂时无法写入，服务仍可处理查询和读取状态；调度器会重试写入，并在确认前暂停新加载。集群托管本地表也会在当前任期内重试确认结果，提交始终受 etcd 主权和任务版本约束。

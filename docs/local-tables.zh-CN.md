# 本地表与数据同步

本地表把外部源表的选定字段加载为 GraphLake 管理的 Parquet 副本。节点和边通过现有 Parquet 数据源读取副本，查询时不再连接外部源。管理流程参考 [PuppyGraph 的本地表](https://docs.puppygraph.com/modeling/data-sources/)与[加载、定时刷新管理](https://docs.puppygraph.com/modeling/managing-the-graph/)；接口和存储格式使用 GraphLake 自身约定。

## 使用流程

1. 配置外部数据源并保存模型草稿。在「图模型 → 本地表」或「数据源 → 本地表与同步」打开管理页。
2. 创建本地表，使用已有的源表浏览器选择表及字段。主键可由多个字段组成。需要增量更新时，同时设置主键与增量字段。
3. 选择创建后立即加载，或稍后执行「加载副本」或「更多操作 → 从源表全量加载」。任务在后台运行，页面可以关闭。历史保留最近 20 次任务，显示手动/定时、加载方式、读取行数、提交后的总行数和结果。
4. 加载成功后选择「更多操作 → 加入模型数据源」，再在节点或边的来源选择器中选择 `local_<表名>.data`；也可点击「更多操作 → 切换映射到本地」，将当前草稿里直接使用该外部表的节点、边及多表输入切换到副本。
5. 检查映射、保存草稿并发布。添加副本不会自动发布模型。若加载字段不足以覆盖已有映射，结构/数据校验会阻止发布；先补齐字段的新表，再切换。

列表顶部展示本地表数、已就绪副本、运行中任务与定时刷新概况，可按表名或来源搜索、按状态筛选。每张表展示刷新策略、最近成功行数和下次运行时间；「立即同步」使用该表配置的更新方式，执行时间线保留任务结果与行数。

源表、连接配置、选定字段、主键、增量字段在创建时固定，独立于后续模型草稿修改。连接凭据继续从原环境变量读取；修改变量后需按现有部署方式重启。若需要更换来源或字段，创建另一张本地表。刷新方式、间隔和超时可随时修改，并有版本冲突检查。

## 更新语义

| 方式 | 行为 |
| --- | --- |
| 全量加载 | 读取所选源表字段，完整写入新副本后原子替换，包含源表当前的插入、更新和删除。未指定主键时保留重复行。 |
| 增量更新 | 首次没有副本时执行全量读取；之后从已提交副本计算最大增量值，读取大于或等于此水位的行，按完整主键覆盖，保留其他旧行。 |
| 定时刷新 | 使用配置的全量或增量方式，每次任务结束后等待指定间隔，再提交下一次任务。失败也按相同间隔重试。 |

增量字段支持整数、日期和时间戳，必须非空。主键必须稳定、非空，在每批来源数据中唯一。每次插入或更新都必须推进该行的增量值；重复读取水位边界并按主键覆盖，使重试及相同水位的行保持幂等。所有连接器都执行最终类型化过滤；整数水位还能传给支持的连接器，PostgreSQL 的类型化过滤也可下推，其他来源的实际读取量取决于其连接器。

这是水位同步，不是数据库日志 CDC。源表物理删除、主键变更、增量字段回退、迟到且低于已提交水位的数据，需要全量刷新。配置频率时应保证来源提交次序与增量值一致；事务在快照之后才提交、但增量值已低于新水位时，也需要全量对账。

启用主键时，发现重复或空主键会使任务失败。增量字段类型不支持、字段丢失、字段类型变化也不会发布新副本。字段新增只有新建表并选择后才加载。任务失败或取消发生在提交前时，保留旧副本。提交点之后到达的取消不会撤销已提交的数据。

数据和水位来自同一个原子替换的 Parquet 文件，不存在先保存水位、后写数据的窗口。进程异常退出后，已提交副本仍可读取；未完成的任务在下次启动时记为「已中断」，可手动重试，已启用的定时任务也会恢复。提交之后、历史写入之前异常退出时，历史可能显示中断，但下一次增量仍以已提交数据为准。

全量加载校验通过后直接提交暂存文件，只编码一次。增量没有新行，或确认本次重读的小批边界记录所有字段值均相同时，仍记录任务结果，但保留原副本。对单列有符号整数主键的小批增量，服务用 Parquet 行组统计和主键扫描定位匹配行，只编码需要替换的行组和传入行。其余行组保留原编码和页索引。在支持 reflink 的 Linux 文件系统上，未改动的文件区间可共享磁盘块，其他文件系统会复制已编码的字节。较大的变更批次、覆盖多数行组的更新和其他主键类型使用完整合并。两种路径都把结果写入临时文件，刷盘后原子替换固定路径的副本。

同一张表只运行一个任务，全服务最多同时运行两个加载任务；手动提交在繁忙时返回冲突或 `429`。定时任务在执行槽空闲后尝试，无积压队列，不补跑停机期间每个错过的时间点。间隔为 30–2592000 秒，单次超时为 1–43200 秒。关闭定时刷新不会取消已开始的任务，可单独点击「取消加载」。

本地副本延续现有 Parquet 来源版本检查。正在读取的查询若与刷新冲突，可能收到来源变化错误，应重新查询；不会把两次刷新混成同一个已验证的快照。模型 YAML 版本不固定本地数据版本，回退模型不会回退表中数据。CSR 仍需按现有流程显式刷新。

## 管理 API

以下路径以 `/api/v1` 为前缀，仅管理员可操作，沿用会话认证和同源 `Origin` 校验。普通建模、发布、查询角色和服务账号不能管理同步任务。配置记录和 API 响应不包含环境变量中的凭据值。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /models/{id}/local-tables` | 列出定义、是否已有副本、刷新配置、下次运行时间和最近历史。 |
| `POST /models/{id}/local-tables` | 创建定义，返回 `201`；本身不触发加载。 |
| `PUT /models/{id}/local-tables/{name}` | 更新刷新方式、间隔和超时，提交当前配置 `revision`。 |
| `POST /models/{id}/local-tables/{name}/load` | 提交后台任务，返回 `202` 和任务 UUID；通过列表的 `history` 跟踪。 |
| `POST /models/{id}/local-tables/{name}/cancel` | 请求取消运行中的任务，返回 `202`。 |

创建请求示例（模型中已有 `ledger` 数据源）：

```json
{
  "model_revision": "模型当前草稿 revision",
  "name": "accounts",
  "source_table": "ledger.public.accounts",
  "columns": ["id", "name", "updated_at"],
  "key_columns": ["id"],
  "watermark_column": "updated_at",
  "mode": "incremental",
  "interval_seconds": 3600,
  "timeout_seconds": 3600
}
```

`model_revision` 不匹配返回 `409`。名称为 1–48 位字母、数字、下划线或连字符，首字符必须是字母或数字。字段最多 512 个，本服务最多 256 张本地表。新表读取已保存草稿中的连接信息，无需模型已发布。禁止以本服务管理的本地副本作为另一个同步任务的来源。

手动加载正文为 `{"mode":"full"}` 或 `{"mode":"incremental"}`。配置更新示例：

```json
{
  "revision": "本地表当前配置 UUID",
  "mode": "incremental",
  "interval_seconds": null,
  "timeout_seconds": 3600
}
```

`interval_seconds: null` 关闭定时刷新。状态为 `running`、`succeeded`、`failed`、`cancelled` 或 `interrupted`。`loaded_rows` 是本次实际写入暂存副本的行数，包含重读水位边界；`total_rows` 是合并后总行数，两者都不是源端扫描行数。时间使用 UTC Unix 毫秒，界面按浏览器时区显示。

## 存储与部署

副本、定义和历史位于 `catalog/.graphlake-local/`。不要只备份模型 YAML；按部署手册停机备份整个 catalog，同时备份外部凭据配置。为旧副本、新副本、来源暂存和查询 spill 预留空间。选择性更新还会短暂存放重写的行组，未改动的区间在支持 reflink 时共享磁盘块。服务启动时取得此目录的独占文件锁；同一目录不能同时交给两个活动服务写入。中断的暂存文件在取得锁后清理。

集群使用本地副本时，所有读取 Worker 必须以相同绝对路径访问该目录；它不提供按 Worker 分片或多副本复制。HA Coordinator 的调度只在持有领导权、恢复验收已通过时启动，并依赖共享文件系统的独占锁。备份恢复页面目前只导入其清单中的外部数据，不包含本地表定义与历史；跨站恢复需在服务停止时单独恢复整个 `.graphlake-local` 目录及其绝对路径，或重新创建、加载副本后再发布使用它的模型。

本地表和配置不随模型下线删除，运行中的同步也不受模型发布状态影响。停用时先关闭定时刷新，保留副本可继续支持历史模型。当前页面不提供删除副本、独立手工插入行、分区保留或 PuppyGraph 的分布/副本数等物理布局设置。

# GraphLake S0 和 S1 实施与验证记录

验证环境为 OrbStack ARM64 Linux，使用 Rust 1.99.1 同一构建配置比较基线 `8189ac3` 和当前 worktree。性能结果来自本地测试夹具。

## 来源查询

SQLite 夹具使用 100,000 行 STRICT 表、整数主键和无索引的 `status` 属性。第 99,998 行为 `BLOCKED`，第 99,999 行为 `blocked`，用于验证二进制等值语义。每条查询预热后交替运行基线与改版各 12 次。指定排序和唯一命中的结果逐条核对。无排序 LIMIT 的结果检查行数及成员资格。

| 查询 | 接收行数，基线 → 改版 | Arrow 字节，基线 → 改版 | 改版 SQLite 全表扫描步数 | P50 / P95，基线 → 改版 |
| --- | ---: | ---: | ---: | ---: |
| `id = 99999 LIMIT 1` | 1 → 1 | 128 → 128 | 0 | 11 / 21 → 5.5 / 7 ms |
| `status = 'blocked' LIMIT 1` | 100,000 → 1 | 2,421,424 → 1,288 | 99,998 | 195 / 283 → 29.5 / 39 ms |
| `LIMIT 1` | 100,000 → 1 | 812,224 → 128 | 0 | 113.5 / 147 → 6 / 8 ms |
| `ORDER BY id DESC LIMIT 1` | 100,000 → 1 | 812,224 → 128 | 0 | 138 / 186 → 8 / 11 ms |

复跑使用 `python3 tests/sqlite_read_benchmark.py <基线 graphlake> <改版 graphlake>`。`sqlite_fullscan_steps` 报告 SQLite 数据语句的全表步数。Arrow 字节统计解码后的数组内存。

SQLite 和 MySQL 对可证明业务键唯一、投影类型安全的直接映射下推普通属性过滤和 LIMIT。按完整整数业务键排序时也可下推 Top-N。SQLite 简单 Cypher 单标签查询通过同一套回归，覆盖属性过滤与 LIMIT。残余条件、重复键和可能混入错误类型的 SQLite 旧表走原校验路径。PostgreSQL 扩展了简单属性等值过滤。ClickHouse 的既有只读 Arrow 路径通过真实服务回归。

## 时间戳增量

在 MySQL 8.4 和 PostgreSQL 16 各创建 100,000 行的 `(tenant_id, id)` 复合主键表，对微秒时间戳建索引。每次先全量加载相同初始数据，再修改 100 条并保留 1 条旧水位边界记录。每个版本预热一轮，采集五轮增量同步耗时。同步后将副本按 ID 排序，核对基线与改版的全部 100,000 行。

| 来源 | 接收行数，基线 → 改版 | 同步 P50，基线 → 改版 | 最慢样本，基线 → 改版 |
| --- | ---: | ---: | ---: |
| MySQL | 100,000 → 101 | 601 → 265 ms | 711 → 327 ms |
| PostgreSQL | 100,000 → 101 | 377 → 217 ms | 592 → 250 ms |

MySQL 基线数据语句在 Performance Schema 记录扫描和发送各 100,000 行。改版连接器接收 101 行，解码字节为 5,288。相同范围的 `EXPLAIN ANALYZE` 显示水位索引返回 101 行。PostgreSQL 的对照计划从顺序扫描 100,000 行、访问 2,157 个共享块，变为水位索引读取 101 行、访问 9 个共享块。PostgreSQL 改版连接器也接收 101 行。

两种数据库都保留已提交水位的含边界过滤和本地类型复核。真实 MySQL 回归还校验同一微秒的旧键更新、下一微秒的新增、重复运行的幂等性以及副本与来源的完整数据值。复合键夹具的同步耗时包含现有 Parquet 合并和写入。

## 回归与阶段边界

- 本地通过 96 项 Rust 核心测试和 8 项必须显式执行的真实服务测试，覆盖 SQLite、PostgreSQL、MySQL、ClickHouse、S3、etcd、权限、取消、Coordinator 重启和 Worker 丢失。通过无 admin feature 的 Rust 检查，以及前端构建和 34 项测试。
- PR、main 和发布候选使用同一套门禁。发布任务依赖门禁完成后才能打包。工作流已在 OrbStack 复跑等价命令，其 GitHub Actions 状态待推送后生成。
- 基线在 100,000 顶点和 1,000,000 条边上复现 Leiden 的 256 MiB 资源拒绝。社区检测额外申请约 293 MiB 时，查询池剩余约 152 MiB。
- S1 的最快路径仍会物化受限结果。按需扫描、更多来源的下推、额外聚合优化和复合键增量写入成本由后续阶段验收。

# 安全分析任务与业务影响检查

GraphLake 为已发布模型提供离职账号和告警调查任务。身份归属来自外部身份库，GraphLake 根据映射、业务时点与来源证据计算结果。任务配置随模型草稿、发布和回退记录管理。

| 任务 | 参数 | 结果 |
| --- | --- | --- |
| `offboarded_account_exposure` | `namespace`、`person_id`、`as_of`、`window_start`、`window_end` | 截至指定时点的直接与一级角色授权，以及离职后的成功、失败和未知访问事件。历史访问按事件时点关联账号归属。 |
| `alert_identity_device_context` | `alert_id`、`window_start`、`window_end` | 告警直接记录的账号和设备、告警时点的身份归属、窗口内的设备使用与共享 IP 线索。多个身份候选保留各自证据。 |

参数中的时间采用 RFC3339，精度至毫秒。事件窗口为 `[window_start, window_end)`，最长 31 天。离职任务要求窗口结束不晚于 `as_of`。告警窗口须包含告警时点。两个接口都继承调用者的查询权限和租户范围。若当前范围内有多个同标识的主体，任务返回歧义错误。租户由服务端确定。

授权结果是来源中的授权事实。只有结果为 `success` 的访问事件产生“成功访问”的发现。拒绝、条件策略、账号停用和实时有效访问范围需要额外证据。共享 IP 和设备共用保留为关联线索。空结果表示在当前输入与范围内未找到记录。

## 配置模型和证据

在图模型工具栏打开「更多工具 → 业务任务」，在「内置任务」中勾选任务并保存草稿。也可以在 YAML 根配置 `tasks`。按 [示例模型](../examples/security-tasks/model.yaml) 映射任务使用的逻辑标签和字段。两个模板有固定的只读 Cypher、标签、带类型的参数和结果分类。现有输入映射可以把任意获准的物理字段映射到这些逻辑标签。模型中的关系方向、租户键和业务类型均参与校验。

- 主体 ID、业务键、证据系统和记录标识为字符串。账号 ID 应在同一租户内含来源命名空间并保持稳定。人以 `tenant_id`、`namespace`、`person_id` 标识。
- 时间列采用 `Int64` UTC epoch 毫秒。`IDENTIFIED_AS` 必须保留全量归属区间。授权和角色关系允许配置 SCD2，须使用 `valid_from_ms` 和 `valid_to_ms`，结束值使用空值。任务按半开区间匹配。
- 每条关系证据按路径顺序包含关系标签、租户、来源系统、记录键、观测时间及可选的来源版本。人员和告警锚点以相同方式提供证据。各路径的证据都来自声明的逻辑字段。
- 证据时间列需声明 `semantics.properties.observed_at_ms.unit: ms`，并按示例配置 `semantics.evidence`。其他任务时间列如果声明单位，同样使用 `ms`。语义文本、记录键和证据版本仍是模型和来源声明。

## 在 MCP 中运行

在查询服务先调用 `list_tasks({"model":"security"})`，取得任务参数和当前 `model_revision`，再调用 `run_task`。例如：

```json
{
  "model": "security",
  "model_revision": "<list_tasks returned revision>",
  "task": "alert_identity_device_context",
  "parameters": {
    "alert_id": "a1",
    "window_start": "1970-01-01T00:00:10Z",
    "window_end": "1970-01-01T00:00:20Z"
  }
}
```

查看 `findings[].kind`、`values` 和 `evidence` 确认结论及其依据。`scope` 记录实际时点和租户，`sources` 按查询步骤返回来源版本，`coverage` 包含找到的各类证据数量、缺少归属和多个归属的情况。来源保留期或新鲜度未知时标为 `unknown`。各步骤可能读取不同来源快照。托管本地表在同一次任务内使用固定代次；启用了严格新鲜度策略的模型也对任务结果执行该策略。要求使用当前 CSR 的模型会拒绝当前任务执行路径。

`execution_status: complete` 表示已完成本次查询；截断或证据缺失时返回 `partial`。失败的查询返回 MCP 工具错误。`validation_report_id` 关联发布时的固定场景检查，适用范围是该套件中的场景。任务只接受准确的生效版本，版本冲突后需重新调用 `list_tasks`。

## 配置固定数据并检查发布

管理员可在「业务任务 → 固定场景」从左侧列表选择或新增场景，窄屏下通过下拉列表切换。在「参数」填写标识、租户和任务参数，在「预期结果」设置主体状态并展开每条发现和证据，在「JSON」精确编辑预期发现或证据。「套件操作」中可载入合成示例、导入 JSON 或编辑固定表数据。完成后点击「保存固定场景」。套件独立于模型草稿保存，大小上限为 1 MiB。请使用合成数据。[示例固定数据](../examples/security-tasks/fixture.json)

- `tables` 以物理输入引用 `source.table` 为键，每项包含有序类型列 `columns` 和合成数据 `rows`。为旧版和候选版任务使用的输入都提供固定数据。回放保留节点、边、过滤、类型转换、键与时态定义，并从同一份本地副本读取。
- `cases` 最多 16 项，每项指定唯一 ID、任务、验证租户、参数、预期主体状态、锚点及最多 50 条预期发现。每个启用任务至少有一个带发现的正向用例，并建议包含错误边界的负向用例。比较保留重复结果及证据，忽略结果行顺序。
- 套件的任务集合是发布要求。删除草稿中的任务无法降低要求。曾通过任务检查的模型在套件缺失时也会拒绝发布。

保存候选草稿后，可打开「更多工具 → 校验业务场景」。首次发布点「预览并发布」，已上线模型可从「更多工具」预览。选「保存并发布」或「发布草稿」直接提交时，服务端同样执行固定场景检查。回退从「版本历史 → 预览回退」打开，比较当前生效版本与选中的归档。展开场景可查看主体状态、发现数量、锚点证据、增删改和预期结果。界面分别显示草稿业务预览、生效版本的业务校验状态，以及结构和数据校验。套件更新后，生效版本可能需要重新预览并发布。

建模 MCP 的 `validate_model_impact` 和 HTTP `POST /api/v1/models/{id}/impact` 可预览草稿，发布者也可用 `POST /api/v1/models/{id}/impact/rollback` 预览归档。HTTP 请求发送目标 `revision` 和 `active_revision`（首次发布时为 `null`），MCP 还需发送 `model`。报告列出映射变化和逐场景结果，候选结果不符时附上预期。超时、截断、证据不完整或缺少固定数据会使场景不可判定并阻止发布。

HTTP 确认可带 `preview: { "report_id": "…" }` 绑定报告。报告标识对应发布或回退操作、目标版本、生效版本、套件及本次校验结果，`not_required` 也返回报告标识。报告不再适用时返回 `impact_preview_changed`。套件变化后重新预览，草稿或生效版本变化后先重新加载模型，再选择是否发布或回退。

同一次检查内，同一版本的各场景复用已绑定固定数据的任务模型。若两个版本相同，或任务绑定后的映射和标签元数据完全一致，该场景执行一次并用于两边的比较。比较保留过滤字面量的表示，例如用于文本过滤的 `-0.0` 和 `0.0`。过滤字面量或证据字段选择变化时，两边分别执行。物理来源连接配置的变化列在映射差异里，场景仍读取运维提供的固定数据。

单机和 HA 的发布及回退都会按当前套件重新执行检查，随后核对版本、权限和套件摘要。历史上通过的版本也须满足当前的证据预期。发布记录持久保存报告标识、套件摘要和任务实现摘要。套件更新或任务实现变化后需要重新校验并发布，过期报告对应的任务无法继续执行。

控制台管理的套件保存在 `.graphlake-<模型标识>.tasks.json`，随 HA 模型状态复制和备份。未在控制台保存时，仍从模型配置目录读取部署提供的 `.tasks-<模型标识>.json`，HA 各 Coordinator 需部署同一份文件。保存后控制台套件优先。管理员也可用 `GET/PUT /api/v1/models/{id}/task-suite`，保存时提交当前套件 `revision`（无套件为 `null`）和 JSON 文本 `content`。并发修改时，已变化的版本会拒绝覆盖。模型版本回退使用当前套件。

## 运行示例

```sh
fixture_dir=$(mktemp -d)
python3 examples/security-tasks/prepare.py "$fixture_dir/catalog"
```

按 [工作台快速开始](quickstart.md#open-the-workbench) 启动服务，将生成的 `catalog` 目录传给 `--catalog-dir`。示例包含两个租户和重复标识。发布 `security` 后，给查询身份配置 `tenant_id = "t1"`，再运行参数化任务。套件验证了有效期结束边界、账号转交、撤销前成功访问、失败与未知结果、多个身份候选以及共享 IP。

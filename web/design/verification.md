## OrbStack PostgreSQL 与 Parquet

管理服务运行在 OrbStack 的 ARM64 Ubuntu。浏览器和 API 使用同一套现有夹具：PostgreSQL 16 的 `ui_fixture.accounts`、`ui_fixture.merchants` 和本地 `payments.parquet`。查询得到账户键 `9007199254740993`、金额 `12.250` 和商户键 `7`，路径为 `CustomerAccount → Payment → Merchant`。同一账户展开为 601 行，预览截断到 500 行。Chrome 下载的 Arrow IPC 文件为 14,984 字节，与同一语句通过 API 下载的文件逐字节一致；在 OrbStack 解码下载文件，确认全部 601 行保留了原始 Int64 和 Decimal128(12, 3) 数值。

自动化集成测试用同一数据契约，在临时 PostgreSQL schema 与 Parquet 文件上验证初始版本归档、草稿与生效版本隔离、校验失败不能发布、过期版本请求被拒绝、回退和重启恢复，以及真实表列发现、三种查询语言、两种图查询的路径信息、500 行和 1 MiB 截断、完整 Arrow 下载与票据单次使用。用 PostgreSQL 表锁确认查询确实在等待，再校验另一个只用 Parquet 的模型，验证它能先完成；随后取消锁等待查询，另测 80 毫秒单次超时和无效超时参数。安全回归覆盖错误的 Host、跨源 Origin、非法模型路径、符号链接和服务器端导出位置禁用。

在配置了可写测试库的环境中，用以下命令复跑。集成测试需要设置 `GRAPHLAKE_ADMIN_TEST_PG_DSN`，会创建独立 schema，Parquet 由测试生成。

```sh
cargo test --locked --workspace --features admin
npm --prefix web test
npm --prefix web run build
```
